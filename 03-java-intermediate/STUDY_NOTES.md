## 1. Objectクラス

### Objectクラス
- Javaのすべてのクラスの最上位にある親クラス
- 親クラスを指定していない場合、暗黙的に`Object`を継承する
- すべてのオブジェクトを`Object`型で参照できる

### Objectの多態性
- `Object`型はすべてのオブジェクトを参照できる
- `Object`型では各クラス固有のメソッドを直接呼び出すことはできない
- 固有の機能を使用する場合はダウンキャストが必要

### Object配列
- `Object[]`を使用すると、異なる型のオブジェクトを同じ配列で扱える

### toString()
- オブジェクトの情報を文字列として返すメソッド
- 必要に応じてオーバーライドし、オブジェクトの情報を分かりやすく表現できる
- `System.out.println()`でオブジェクトを出力すると`toString()`が呼び出される

### equals()
- `==`：参照値を比較する（同一性）
- `equals()`：論理的に同じ値かを比較するために使用する（同値性）
- `Object`のデフォルトの`equals()`は`==`による比較
- 値を基準に比較したい場合は`equals()`をオーバーライドする

## 2. 不変オブジェクト

### 基本型と参照型の共有
- 基本型は値そのものをコピーして使用する
- 参照型はオブジェクトの参照値をコピーする
- 複数の変数が同じオブジェクトを参照することがある

### 共有参照と副作用
- 同じオブジェクトを複数の変数で共有している場合、一方から値を変更すると他方にも影響する
- オブジェクトの変更が他の処理にも影響を与えることを副作用（Side Effect）という
- 参照型ではオブジェクトの共有による副作用に注意する必要がある

### 不変オブジェクト
- オブジェクトを生成した後、内部の状態を変更できないオブジェクト
- フィールドを`final`にすることで、生成後の再代入を防ぐことができる
- 値を変更できないため、共有参照による副作用を防ぐことができる
- 安全にオブジェクトを共有できる

### 値を変更する場合
- 不変オブジェクト自身の値は変更しない
- 値を変更したい場合は、変更後の値を持つ新しいオブジェクトを生成して返す
- 元のオブジェクトの状態はそのまま維持される

### 不変オブジェクトのメリット
- オブジェクトの状態が意図せず変更されることを防げる
- 複数の場所から同じオブジェクトを参照しても安全に使用できる
- コードの動作を予測しやすくなる

## 3. Stringクラス

### Stringクラス
- Javaで文字列を扱うために使用するクラス
- `String`は参照型だが、文字列リテラルを使用して簡単に生成できる
- 文字列リテラルはString Poolで管理され、同じ文字列を効率的に再利用できる

### Stringの比較
- `==`：Stringオブジェクトの参照値を比較する
- `equals()`：文字列の内容が同じかを比較する
- 文字列の内容を比較する場合は`equals()`を使用する
- String Poolの影響で`==`でも`true`になる場合があるため、文字列比較には`==`を使用しない

### Stringの不変性
- `String`は不変（Immutable）なクラス
- 一度生成されたStringオブジェクトの文字列は変更できない
- 文字列を変更する処理を行うと、既存のオブジェクトを変更するのではなく新しいStringオブジェクトが生成される
- 不変であるため、安全に文字列を共有できる

### Stringの主なメソッド
- `length()`：文字列の長さを取得する
- `charAt()`：指定した位置の文字を取得する
- `substring()`：文字列の一部を取得する
- `indexOf()`：指定した文字列の位置を検索する
- `contains()`：指定した文字列が含まれているか確認する
- `startsWith()` / `endsWith()`：指定した文字列で始まる、または終わるか確認する
- `toLowerCase()` / `toUpperCase()`：小文字・大文字に変換する
- `trim()` / `strip()`：文字列の前後の空白を取り除く
- `replace()`：文字列を置換する
- `split()`：指定した区切り文字で文字列を分割する

### StringBuilder
- `StringBuilder`は内容を変更できる可変（Mutable）な文字列クラス
- 文字列を繰り返し結合・変更する場合に使用する
- `append()`などのメソッドで同じオブジェクトの内容を変更できる
- 最後に`toString()`を使用して`String`に変換できる

### Stringの最適化
- `String`は不変のため、文字列を変更するたびに新しいオブジェクトが生成される
- 単純な文字列の結合では、Javaが内部的に最適化を行う場合がある
- ループなどで文字列を繰り返し結合する場合は`StringBuilder`を使用すると効率が良い
- 状況に応じて`String`と`StringBuilder`を使い分けることが重要

### メソッドチェイニング
- メソッドの戻り値として自分自身のオブジェクトを返すことで、複数のメソッドを連続して呼び出せる
- `StringBuilder`では`append()`などのメソッドが自身を返すため、メソッドチェイニングが可能
- 処理を連続して記述できるため、コードを簡潔に書くことができる

## 4. ラッパークラス・Classクラス

### ラッパークラス
- 基本型（プリミティブ型）をオブジェクトとして扱うためのクラス
- `int`は`Integer`、`long`は`Long`、`double`は`Double`などのラッパークラスを使用する
- 基本型では`null`を使用できないが、ラッパークラスでは`null`を使用できる
- オブジェクトとして扱えるため、コレクションなど基本型を直接使用できない場合に利用できる

### ボクシングとアンボクシング
- 基本型の値をラッパークラスのオブジェクトに変換することをボクシングという
- ラッパークラスのオブジェクトから基本型の値を取り出すことをアンボクシングという
- `Integer.valueOf()`などを使用してボクシングできる
- `intValue()`などを使用してアンボクシングできる

### オートボクシングとオートアンボクシング
- Javaでは基本型とラッパークラスの変換を自動的に行うことができる
- 基本型からラッパークラスへの自動変換をオートボクシングという
- ラッパークラスから基本型への自動変換をオートアンボクシングという
- 自動変換により、基本型とラッパークラスを簡潔に扱うことができる

### ラッパークラスの主なメソッド
- `valueOf()`：基本型や文字列からラッパーオブジェクトを生成する
- `parseInt()`など：文字列を基本型に変換する
- `compareTo()`：値の大小を比較する
- `Integer.max()` / `Integer.min()`：2つの値から最大値・最小値を取得する

### Classクラス
- Javaのクラス情報を扱うためのクラス
- `Class`オブジェクトからクラス名やパッケージ名などの情報を取得できる
- `クラス名.class`、`インスタンス.getClass()`、`Class.forName()`などでClassオブジェクトを取得できる
- 実行時にクラスの情報を調べたり操作したりする仕組みをリフレクションという

### Systemクラス
- システムに関連する機能を提供するクラス
- `System.currentTimeMillis()`：現在時刻をミリ秒単位で取得する
- `System.nanoTime()`：経過時間の測定などに使用できる高精度な時間を取得する
- `System.getenv()`：環境変数を取得する
- `System.getProperties()`：システムプロパティを取得する
- `System.exit()`：プログラムを終了する

### Mathクラス
- 数学的な計算を行うための便利なメソッドを提供するクラス
- `Math.max()` / `Math.min()`：最大値・最小値を取得する
- `Math.abs()`：絶対値を取得する
- `Math.ceil()`：切り上げ
- `Math.floor()`：切り捨て
- `Math.round()`：四捨五入
- `Math.pow()`：べき乗を計算する
- `Math.sqrt()`：平方根を計算する

### Randomクラス
- 乱数を生成するために使用するクラス
- `nextInt()`、`nextDouble()`、`nextBoolean()`などを使用してさまざまな型の乱数を生成できる
- `nextInt(bound)`を使用すると、指定した範囲内の乱数を生成できる
- シード（seed）を指定すると、同じ乱数の並びを再現できる

## 5. 列挙型 - ENUM

### 文字列と型安全性
- 文字列を使用して状態や種類を表現すると、誤った文字列を入力してもコンパイル時にエラーを検出できない
- 文字列による値の管理では、タイプミスや存在しない値が使用される可能性がある
- 定数を使用することで入力ミスを減らすことはできるが、型自体は`String`のままである
- `String`型である以上、定義していない文字列を渡すこともできるため、完全な型安全性は保証できない

### 型安全な列挙型パターン
- 使用できる値を特定のオブジェクトだけに制限することで型安全性を高める方法
- 使用可能な値を`static final`のオブジェクトとしてあらかじめ定義する
- コンストラクタを`private`にすることで、外部から新しいオブジェクトを生成できないようにする
- 定義されたオブジェクトだけを使用できるため、誤った値が使用されることを防げる
- このような設計を型安全な列挙型パターン（Type-Safe Enum Pattern）という

### enum
- Javaでは型安全な列挙型を簡単に定義するために`enum`を使用できる
- あらかじめ定義された定数だけを使用できる専用の型を作成できる
- 定義されていない値は使用できないため、コンパイル時に誤りを検出できる
- 文字列と比較してタイプミスを防ぎやすく、コードの安全性と可読性が高くなる

### Enumの特徴
- Enumで定義された各定数は単なる文字列ではなく、それぞれEnum型のオブジェクト
- Enumは内部的に`java.lang.Enum`を継承している
- Enumのオブジェクトを外部から直接生成することはできない
- 定義されたEnum定数のみを使用できるため、型安全性を保証しやすい
- Enum同士は同じ型として比較できるため、安全に値を扱うことができる

### Enumの主なメソッド
- `values()`：定義されているすべてのEnum定数を配列として返す
- `valueOf()`：指定した文字列と同じ名前のEnum定数を返す
- `name()`：Enum定数の名前を文字列として返す
- `ordinal()`：Enum定数が定義された順番を0から始まる数値として返す
- `toString()`：Enum定数を文字列として表現する

### values()
- Enumに定義されているすべての定数を取得できる
- 戻り値はEnum型の配列
- 拡張for文などを使用して、すべてのEnum定数を順番に処理できる

### valueOf()
- 文字列から対応するEnum定数を取得するために使用する
- Enumに定義されている名前と完全に一致する必要がある
- 存在しない名前を指定すると例外が発生する

### name()
- Enum定数として定義された名前を文字列として取得する
- 定義されている名前をそのまま返す
- Enumの名前を文字列として扱う必要がある場合に使用できる

### ordinal()
- Enum定数が定義された順番を数値として取得する
- 最初の定数は`0`、次の定数は`1`のように番号が割り当てられる
- Enumの定義順を変更すると値も変わるため、ビジネスロジックやデータ保存などに使用することは避ける

### Enumにフィールドを追加する
- Enumにも通常のクラスと同じようにフィールドを持たせることができる
- 各Enum定数ごとに異なる値を保持できる
- Enum定数と、その定数に関連するデータを一緒に管理できる
- 状態や種類に関連する値をEnum内部で管理することで、コードをまとめやすくなる

### Enumのコンストラクタ
- Enumにもコンストラクタを定義できる
- 各Enum定数を定義するときに、コンストラクタへ値を渡すことができる
- Enumのコンストラクタは外部から直接呼び出すことはできない
- Enum定数を生成するときに内部的に使用される

### Enumにメソッドを追加する
- Enumにはフィールドだけでなくメソッドも定義できる
- Enumが持つ値を利用して、関連する処理をEnum自身に持たせることができる
- Enumに関連するデータとロジックを同じ場所で管理できる

### Enumを利用したリファクタリング
- Enumを使用することで、文字列による条件分岐を減らすことができる
- Enumごとに必要な値をフィールドとして持たせることで、`if`や`switch`による分岐を整理できる
- Enum自身に関連する処理をメソッドとして持たせることで、処理を一か所にまとめることができる
- 新しい種類を追加するときも、Enum側に必要な値や処理を追加することで変更箇所を減らせる

### Enumを利用するメリット
- 使用できる値を限定できるため、型安全性が高い
- 存在しない値やタイプミスをコンパイル時に検出しやすい
- 文字列定数よりコードの意図が分かりやすい
- IDEの自動補完を利用できる
- 関連するデータと処理をEnum内部にまとめることができる
- 条件分岐を減らし、コードの可読性や保守性を高めることができる

### Enumを使用する場面
- 状態や種類など、使用できる値があらかじめ決まっている場合に適している
- 会員ランク、注文状態、曜日、権限、決済状態などの管理に利用できる
- 単なる文字列ではなく、意味を持った専用の型として値を扱いたい場合に使用する

## 6. 日付と時刻

### 日付と時刻の基本
- Javaでは日付や時刻を扱うために`java.time`パッケージを使用する
- 日付、時刻、タイムゾーンなど、目的に応じて異なるクラスを使用する
- `java.time`の主要なクラスは不変（Immutable）オブジェクトとして設計されている
- 日付や時刻を変更する場合、元のオブジェクトを変更せず、新しいオブジェクトを生成して返す

### LocalDate
- 日付（年・月・日）を扱うためのクラス
- 時刻やタイムゾーンの情報は持たない
- `LocalDate.now()`：現在の日付を取得する
- `LocalDate.of()`：指定した年月日から日付を生成する
- `getYear()`、`getMonthValue()`、`getDayOfMonth()`などで各情報を取得できる

### LocalTime
- 時刻（時・分・秒・ナノ秒）を扱うためのクラス
- 日付やタイムゾーンの情報は持たない
- `LocalTime.now()`：現在の時刻を取得する
- `LocalTime.of()`：指定した時刻を生成する
- `getHour()`、`getMinute()`、`getSecond()`などで各情報を取得できる

### LocalDateTime
- 日付と時刻を一緒に扱うためのクラス
- `LocalDate`と`LocalTime`を組み合わせた情報を持つ
- タイムゾーンの情報は持たない
- `LocalDateTime.now()`：現在の日付と時刻を取得する
- `LocalDateTime.of()`：指定した日付と時刻からオブジェクトを生成する

### ZoneId
- タイムゾーンを表すためのクラス
- `Asia/Seoul`、`Asia/Tokyo`などの地域IDを使用してタイムゾーンを指定できる
- `ZoneId.of()`：指定した地域のタイムゾーンを取得する
- 地域ごとの時差やサマータイムなどのルールを扱うことができる

### ZonedDateTime
- 日付・時刻・タイムゾーンを一緒に扱うためのクラス
- 特定の地域における日時を表現できる
- `ZonedDateTime.now()`：現在の日付・時刻・タイムゾーンを取得する
- 異なるタイムゾーン間で日時を変換する場合に利用できる

### OffsetDateTime
- 日付・時刻とUTCからの時差（Offset）を扱うためのクラス
- `+09:00`のようなUTCとの差を保持する
- `ZonedDateTime`とは異なり、`Asia/Tokyo`のような地域情報は持たない
- 地域のタイムゾーンルールが不要で、UTCとの差だけを扱いたい場合に利用できる

### Instant
- UTCを基準として特定の瞬間を表すためのクラス
- 世界共通の時間軸上の一点を表現できる
- `Instant.now()`：現在の瞬間を取得する
- 1970年1月1日00:00:00 UTCを基準としたエポック時間を利用する
- サーバー間の時刻管理やログなど、機械中心の時間処理に利用できる

### Duration
- 時間を基準とした間隔を表すためのクラス
- 時・分・秒・ナノ秒などの時間差を扱う
- `Duration.between()`：2つの時刻の間隔を取得する
- 時間を基準とした処理に適している

### Period
- 日付を基準とした期間を表すためのクラス
- 年・月・日単位の期間を扱う
- `Period.between()`：2つの日付の期間を取得する
- 日付を基準とした処理に適している

### DurationとPeriodの違い
- `Duration`：時・分・秒など、時間を基準とした間隔を扱う
- `Period`：年・月・日など、日付を基準とした期間を扱う
- 求めたい差の種類に応じて使い分ける必要がある

### ChronoUnit
- 日付や時刻の単位を表すEnum
- `YEARS`、`MONTHS`、`DAYS`、`HOURS`、`MINUTES`、`SECONDS`などが用意されている
- 日付や時刻に特定の単位を加算・減算する場合に利用できる
- `between()`を使用すると、2つの日付や時刻の差を指定した単位で取得できる

### ChronoField
- 日付や時刻が持つ特定のフィールドを表すEnum
- `YEAR`、`MONTH_OF_YEAR`、`DAY_OF_MONTH`、`HOUR_OF_DAY`などが用意されている
- `get()`を使用して指定したフィールドの値を取得できる
- `with()`を使用して指定したフィールドの値を変更できる

### isSupported()
- 日付や時刻のオブジェクトが特定のフィールドや単位をサポートしているか確認する
- すべての日付・時刻クラスが同じ情報を持っているわけではない
- 例えば`LocalDate`は時刻情報を持たないため、時間に関するフィールドは使用できない
- サポートしていないフィールドを使用すると例外が発生する場合がある

### 日付と時刻の取得
- 日付や時刻の値は専用のgetterメソッドを使用して取得できる
- `getYear()`：年を取得する
- `getMonthValue()`：月を数値で取得する
- `getDayOfMonth()`：日を取得する
- `getHour()`：時を取得する
- `getMinute()`：分を取得する
- `ChronoField`を使用して値を取得することもできる

### plus()
- 日付や時刻に指定した値を加算するために使用する
- `plusYears()`、`plusMonths()`、`plusDays()`などの専用メソッドを使用できる
- `ChronoUnit`を指定して加算することもできる
- 元のオブジェクトは変更されず、変更後の新しいオブジェクトが返される

### minus()
- 日付や時刻から指定した値を減算するために使用する
- `minusYears()`、`minusMonths()`、`minusDays()`などの専用メソッドを使用できる
- 元のオブジェクトは変更されず、変更後の新しいオブジェクトが返される

### with()
- 日付や時刻の特定の値を指定した値に変更するために使用する
- `withYear()`、`withMonth()`、`withDayOfMonth()`などを使用できる
- `plus()`が現在の値を基準に加算するのに対して、`with()`は指定した値に変更する
- 元のオブジェクトは変更されず、新しいオブジェクトが返される

### TemporalAdjusters
- 日付を特定の条件に合わせて調整するための機能
- 月の初日や最終日、次の特定の曜日などを簡単に求めることができる
- `firstDayOfMonth()`：その月の最初の日を取得する
- `lastDayOfMonth()`：その月の最後の日を取得する
- `next()`：次の指定した曜日を取得する
- 複雑な日付計算を簡潔に記述できる

### 日付と時刻の差
- 2つの日付や時刻の差は目的に応じて異なる方法で求める
- `ChronoUnit.between()`：指定した単位で差を取得する
- `Duration.between()`：時間を基準とした差を取得する
- `Period.between()`：日付を基準とした差を取得する
- 必要な単位や目的に応じて使い分けることが重要

### 日付と時刻のフォーマット
- 日付や時刻を指定した形式の文字列に変換することをフォーマットという
- `DateTimeFormatter`を使用して表示形式を指定できる
- `ofPattern()`を使用して任意の形式を定義できる
- `format()`を使用して日付・時刻オブジェクトを文字列に変換できる

### DateTimeFormatter
- 日付や時刻と文字列を相互変換するために使用するクラス
- `yyyy`：年
- `MM`：月
- `dd`：日
- `HH`：時
- `mm`：分
- `ss`：秒
- `yyyy-MM-dd`や`yyyy-MM-dd HH:mm:ss`などの形式を指定できる

### パース
- 文字列を日付や時刻のオブジェクトに変換することをパースという
- `LocalDate.parse()`や`LocalDateTime.parse()`などを使用する
- `DateTimeFormatter`を指定することで、任意の形式の文字列を変換できる
- 文字列の形式とフォーマッターの形式が一致している必要がある

### タイムゾーンの変換
- `ZonedDateTime`を使用すると異なる地域の時刻へ変換できる
- `withZoneSameInstant()`を使用すると、同じ瞬間を維持したまま別のタイムゾーンに変換できる
- 国や地域をまたぐ日時処理ではタイムゾーンを考慮する必要がある

### 日付の繰り返し処理
- `plusDays()`などを使用して日付を順番に進めながら繰り返し処理できる
- 開始日から終了日までの日付を処理する場合などに利用できる
- `isBefore()`、`isAfter()`、`isEqual()`などを使用して日付を比較できる

### カレンダーの作成
- `LocalDate`、`DayOfWeek`などを組み合わせることでカレンダーを作成できる
- 月の初日や最終日、曜日などの情報を利用して日付の位置を計算できる
- 日付APIを組み合わせることで実践的な日付処理を実装できる

### 日付と時刻の使い分け
- 日付だけを扱う場合：`LocalDate`
- 時刻だけを扱う場合：`LocalTime`
- 日付と時刻を扱う場合：`LocalDateTime`
- タイムゾーンを含めて扱う場合：`ZonedDateTime`
- UTCとの時差を扱う場合：`OffsetDateTime`
- 世界共通の瞬間を扱う場合：`Instant`
- 時間の間隔を扱う場合：`Duration`
- 日付の期間を扱う場合：`Period`

## 7. ネストクラス・内部クラス1

### ネストクラス
- クラスの中に別のクラスを定義することをネストクラス（Nested Class）という
- ネストクラスは、定義する位置や`static`の有無によって種類が分かれる
- ネストクラスには静的ネストクラス、内部クラス、ローカルクラス、匿名クラスがある
- ネストクラスは、特定のクラス同士が密接に関連している場合に利用できる

### ネストクラスの種類
- 静的ネストクラス：`static`を付けて定義する
- 内部クラス：`static`を付けずにクラスのメンバーとして定義する
- ローカルクラス：メソッドなどのコードブロック内に定義する
- 匿名クラス：クラス名を持たない特殊なローカルクラス
- 静的ネストクラス以外は、内部クラスの種類として扱われる

### 静的ネストクラス
- クラス内部に`static class`として定義するクラス
- 外側クラスのインスタンスには所属しない
- 自分自身のインスタンスメンバーにはアクセスできる
- 外側クラスの静的メンバーにはアクセスできる
- 外側クラスのインスタンスメンバーには直接アクセスできない
- 同じクラス内部に定義されているため、外側クラスの`private`メンバーにもアクセスできる

### 静的ネストクラスの生成
- 外側クラスのインスタンスを生成しなくても作成できる
- `外側クラス.ネストクラス`の形式でアクセスする
- `new 外側クラス.ネストクラス()`の形式でインスタンスを生成する
- 外側クラスのインスタンスと静的ネストクラスのインスタンスは互いに独立している

### 静的ネストクラスのアクセス
- 外部からネストクラスへアクセスする場合は`外側クラス.ネストクラス`を使用する
- 外側クラス自身から内部のネストクラスを使用する場合は、外側クラス名を省略できる
- ネストクラスを外部から頻繁に直接使用する場合は、通常のクラスとして分離した方がよい場合がある

### 静的ネストクラスの活用
- 特定のクラス内部でのみ使用するクラスをまとめる場合に利用できる
- 外部から使用する必要のないクラスを隠すことができる
- 関連するクラスを同じ場所に配置することで、論理的にグループ化できる
- `private static class`として定義すると、外部から直接生成できないようにできる
- クラスの用途をコード上でより明確に表現できる

### ネストクラスを使用するメリット
- 関連するクラスを論理的にグループ化できる
- パッケージに不要なクラスを外部公開せずに済む
- 外側クラスの`private`メンバーへアクセスできる
- 不要な`public`メソッドを減らすことでカプセル化を高めることができる

### 内部クラス
- 外側クラスのメンバーとして定義される`static`を持たないクラス
- 外側クラスのインスタンスに所属する
- 自分自身のメンバーにアクセスできる
- 外側クラスのインスタンスメンバーに直接アクセスできる
- 外側クラスの静的メンバーにもアクセスできる
- 外側クラスの`private`メンバーにもアクセスできる

### 内部クラスの生成
- 内部クラスを生成するには、先に外側クラスのインスタンスが必要
- `外側クラスのインスタンス.new 内部クラス()`の形式で生成する
- 内部クラスのインスタンスは、自分を生成した外側クラスのインスタンスを参照する
- 外側クラスの内部で生成する場合は`new 内部クラス()`のように簡潔に記述できる

### 静的ネストクラスと内部クラスの違い
- 静的ネストクラスには`static`が付く
- 内部クラスには`static`が付かない
- 静的ネストクラスは外側クラスのインスタンスに所属しない
- 内部クラスは外側クラスのインスタンスに所属する
- 静的ネストクラスは外側クラスのインスタンスメンバーへ直接アクセスできない
- 内部クラスは外側クラスのインスタンスメンバーへ直接アクセスできる

### 内部クラスの活用
- 外側クラスと強く関連し、外側クラスのインスタンス情報を使用する場合に利用できる
- 外側クラスでのみ使用されるクラスを内部にまとめることができる
- 内部クラスから外側クラスのフィールドへ直接アクセスできる
- 内部クラス専用のGetterを外部公開する必要がなくなる
- 外部へ公開する情報を減らし、カプセル化を高めることができる

### カプセル化
- オブジェクトの内部情報を必要以上に外部へ公開しないことが重要
- 内部クラスを利用すると、外部公開用のGetterなどを減らせる場合がある
- 必要なメソッドだけを外部公開することでクラスの責任を明確にできる
- 内部実装を外部から隠すことで、コードの変更による影響を減らしやすくなる

### 同じ名前の変数へのアクセス
- ローカル変数、内部クラスのフィールド、外側クラスのフィールドが同じ名前になる場合がある
- 同じ名前が存在する場合、より近いスコープにある変数が優先される
- `value`：最も近いローカル変数へアクセスする
- `this.value`：現在の内部クラスのインスタンス変数へアクセスする
- `外側クラス名.this.value`：外側クラスのインスタンス変数へアクセスする

### シャドーイング
- 同じ名前の変数によって、外側にある変数が見えにくくなることをシャドーイング（Shadowing）という
- 名前が重複した場合でも`this`や`外側クラス名.this`を使用して明示的にアクセスできる
- 可読性を高めるため、可能であれば最初から異なる変数名を使用する方が分かりやすい

## 8. ネストクラス・内部クラス2

### ローカルクラス
- メソッドなどのコードブロック内に定義するクラスをローカルクラス（Local Class）という
- ローカルクラスは定義されたコードブロックの内部でのみ使用できる
- 通常のクラスと同じようにフィールドやメソッドを持つことができる
- 特定のメソッド内部でのみ使用するクラスを定義したい場合に利用できる

### ローカルクラスからのアクセス
- ローカルクラスは自分自身のメンバーへアクセスできる
- 外側クラスのインスタンスメンバーや静的メンバーへアクセスできる
- ローカルクラスが定義されているメソッドのローカル変数にもアクセスできる
- ただし、アクセスするローカル変数には一定の制約がある

### ローカル変数のライフサイクル
- ローカル変数はメソッドが呼び出されたときに生成される
- メソッドの処理が終了すると、そのメソッドで使用されていたローカル変数も役割を終える
- 一方、ローカルクラスから生成されたオブジェクトはメソッド終了後も他の場所から参照される可能性がある
- そのため、ローカルクラスのオブジェクトとローカル変数ではライフサイクルが異なる場合がある

### 変数キャプチャ
- ローカルクラスが外側のローカル変数を使用する場合、その値をキャプチャして使用する
- これを変数キャプチャ（Variable Capture）という
- キャプチャされた値はローカルクラスのオブジェクト側で保持される
- そのため、元のメソッドの処理が終了した後でもキャプチャした値を使用できる

### キャプチャできる変数
- ローカルクラスからアクセスできるローカル変数は`final`または実質的に`final`である必要がある
- `final`を明示的に付けた変数は、値を再代入できない
- `final`を付けていなくても、一度代入した後に値を変更していない変数は実質的に`final`（Effectively Final）として扱われる
- 実質的に`final`な変数であれば、ローカルクラスからアクセスできる

### 実質的にfinal
- `final`キーワードを付けていなくても、初期化後に値を変更していない変数を実質的に`final`という
- ローカルクラスから使用しているローカル変数の値を後から変更すると、コンパイルエラーが発生する
- キャプチャされた値と元のローカル変数の値が異なる状態になることを防ぐための制約
- 値を変更しないことが保証されることで、安全に変数をキャプチャできる

### 変数キャプチャが必要な理由
- ローカル変数とローカルクラスのオブジェクトではライフサイクルが異なる場合がある
- ローカルクラスのオブジェクトがメソッド終了後も存在する場合、元のローカル変数へ直接アクセスすることはできない
- そのため、必要な値をローカルクラス側へコピーして保持する
- キャプチャする値を変更できないようにすることで、値の不整合を防ぐことができる

### 匿名クラス
- クラス名を持たない特殊なローカルクラスを匿名クラス（Anonymous Class）という
- クラスを別途定義せず、オブジェクトを生成すると同時にクラスの内容を定義できる
- 主にインターフェースの実装や親クラスの継承を一度だけ使用する場合に利用する
- 名前がないため、同じ匿名クラスから別のインスタンスを直接生成することはできない

### 匿名クラスの基本構造
- `new インターフェース名() { ... }`のような形式で記述する
- `new`の後にインターフェースや親クラスを指定し、その場で必要なメソッドをオーバーライドする
- クラスの定義とオブジェクトの生成を同時に行うことができる
- 一度しか使用しない簡単な実装クラスを別ファイルとして作成する必要がなくなる

### 匿名クラスとインターフェース
- インターフェース型の変数に匿名クラスのオブジェクトを代入できる
- 匿名クラス内部でインターフェースに定義されたメソッドをオーバーライドする
- 同じインターフェースを基準に、異なる処理を持つ複数の匿名クラスを作成できる
- 呼び出す側は具体的な実装ではなく、インターフェース型として扱うことができる

### 匿名クラスの活用
- 一度だけ使用する処理を簡潔に定義したい場合に利用できる
- 実装クラスを別途作成する必要がなくなり、関連する処理を使用する場所の近くに記述できる
- 共通処理の中で変更される部分だけを匿名クラスとして渡すことができる
- インターフェースを利用することで、実行する処理を外部から柔軟に渡すことができる

### 共通処理と変更される処理の分離
- 複数の処理に共通する部分と、それぞれ異なる部分を分離することができる
- 共通する処理は1つのメソッドにまとめる
- 変更される処理はインターフェースのメソッドとして定義する
- 呼び出す側で匿名クラスを作成し、必要な処理だけを実装して渡す
- 重複したコードを減らし、処理の役割を明確にできる

### 匿名クラスを使用するメリット
- 一度だけ使用するクラスを別途定義する必要がない
- クラスの定義とオブジェクトの生成を同時に行える
- コード量を減らし、処理を使用する場所の近くにまとめることができる
- インターフェースを利用することで、異なる処理を同じ型として扱うことができる
- 共通処理と変更される処理を分離しやすくなる

### ローカルクラスと匿名クラスの違い
- ローカルクラスはクラス名を持つ
- 匿名クラスはクラス名を持たない
- ローカルクラスは同じコードブロック内で複数回インスタンスを生成できる
- 匿名クラスは定義と同時にオブジェクトを生成する
- 一度だけ使用する簡単な実装では匿名クラスを利用するとコードを簡潔にできる

### ネストクラス・内部クラスの使い分け
- 静的ネストクラス：外側クラスのインスタンス情報を必要としない場合
- 内部クラス：外側クラスのインスタンス情報を利用する場合
- ローカルクラス：特定のメソッドやコードブロック内でのみ使用する場合
- 匿名クラス：一度だけ使用する簡単な実装が必要な場合
- クラス同士の関係や使用範囲に応じて適切な種類を選択することが重要

## 9. 例外処理1 - 理論

### 例外処理が必要な理由
- プログラムの実行中には、さまざまなエラー状況が発生する可能性がある
- ネットワーク接続の失敗や不正な入力など、正常に処理できない状況に対応する必要がある
- エラーが発生した場合でも、状況に応じて適切な処理を行うことが重要
- Javaでは、このような問題に対応するために例外（Exception）を使用する

### エラー状況と問題点
- 処理が失敗しても、エラーを適切に通知できなければ呼び出し側は問題を判断できない
- 正常な処理とエラー処理が混在すると、コードが複雑になりやすい
- エラーを確認する処理が漏れると、そのまま後続処理が実行される可能性がある
- エラーを適切に伝える仕組みが必要になる

### 戻り値を利用したエラー処理
- メソッドの戻り値を利用して、処理の成功・失敗を表現することができる
- 特定の値をエラーとして返し、呼び出し側で戻り値を確認する方法がある
- 呼び出し側は戻り値を確認し、正常な処理かエラー処理かを判断する

### 戻り値によるエラー処理の限界
- 正常な戻り値とエラーを表す値が混在する
- 呼び出し側で毎回エラーを確認する必要がある
- エラー確認を忘れても、コンパイル時に検出できない場合がある
- 正常処理とエラー処理が混ざり、コードが複雑になる可能性がある
- Javaでは、これらの問題を解決するために例外処理を使用する

### Javaの例外階層
- Javaでは、例外やエラーをクラスとして扱う
- 例外に関するクラスの最上位には`Throwable`がある
- `Throwable`の主な子クラスとして`Error`と`Exception`がある
- `Exception`の子クラスとして`RuntimeException`がある

```text
Object
 └─ Throwable
     ├─ Error
     └─ Exception
         └─ RuntimeException
